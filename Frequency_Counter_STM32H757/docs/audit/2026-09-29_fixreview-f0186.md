## Souhrn

Pokračování dnešního přezkumu vlastních oprav (po F-0197→F-0199). F-0186
je největší a nejrozsáhlejší z „kritického průchodu" 2026-09-27 — mění
jednotku délky okna z nanosekund (floor od FPGA) na přesné tiky/pikosekundy
napříč pěti funkcemi a čtyřmi soubory. Vysoké riziko přesně téhle třídy
chyby („převod se udělal na některých místech, ne na všech"), takže je to
přirozený kandidát pro důkladný přezkum.

**Verdikt: funkční, žádný nový nález.** Matematika `fpga_freq_dt_ticks()`
je staticky ověřena (round-trip pro sudé i liché `dt`, viz níže) a **všechna**
místa, která dřív dělila `gate_time_ns` přímo pro hi-res výpočet, byla
převedena. Zbylá přímá použití `gate_ns` jsou buď diagnostická (bez dopadu
na přesnost), nebo mají toleranci o pět až šest řádů větší, než je chyba
floor zaokrouhlení (~2×10⁻⁹ relativně) — legitimní výjimky, ne přehlédnuté
sourozence.

## Ověřená matematika `fpga_freq_dt_ticks()`

```c
uint64_t fpga_freq_dt_ticks(uint64_t gate_ns)
{
    return (gate_ns * 2000ull + FPGA_TICK_PS) / (2ull * FPGA_TICK_PS);
}
```

S `FPGA_TICK_PS=2500`: `(gate_ns·2000 + 2500) / 5000` = `(4·gate_ns + 5) / 10`
(po vydělení 500) = `floor(4·gate_ns/10 + 0,5)` = `round(gate_ns / 2,5)`.

Ruční ověření na obou třídách vstupu (FPGA posílá `gate_ns = floor(dt·2,5)`,
tj. `(dt·5)>>1` v celočíselné aritmetice):
- **sudé `dt`:** `dt·2,5` je celé číslo → `gate_ns = dt·2,5` přesně →
  `round(gate_ns/2,5) = dt` přesně. ✅
- **liché `dt`:** `dt·5` je liché, `(dt·5)>>1 = (dt·5-1)/2` → `gate_ns/2,5 =
  dt - 0,2` → `round(dt - 0,2) = dt` (0,2 < 0,5, zaokrouhlí se zpět nahoru). ✅

Přesně odpovídá vlastnímu selftestu v `fpga_freq_select_selftest()`
(`DT[] = {100000000, 100000001, 8600000001, 1, 2}` — sudé, liché, dlouhé
21,5s okno, hraniční hodnoty) a hi-res vektoru `9 999 999,900000001 Hz`
(floor hradla by dal o 2×10⁻⁹ víc). Přetečení: `gate_ns` max ~21,5×10⁹ ns
(protokolový strop okna) → `gate_ns·2000` ~4,3×10¹³, hluboko pod
`uint64_t` mezí ~1,8×10¹⁹.

## Co bylo zkontrolováno a je v pořádku

- **Jednotková konzistence ns→ps** v akumulátoru (`fpga_acc_add`,
  `fpga_stat_pop`, `fpga_acc_take`): přepočet `1e4/gate_ns` (ns) →
  `1e7/gate_ps` (ps) odpovídá posunu měřítka o 3 řády (1e9→1e12), ověřeno
  ručním přepočtem vzorce `f = cyc_e5·1e-5 / (gate·jednotka)`.
- **Práh uzavření vzorku statistiky** (`2·gate_sum + gate >= 2s`) — správně
  přeškálován `2e9`(ns) → `2e12`(ps), stejný poměr.
- **`meas_present.c` selftest** — přepočítané vstupní konstanty
  (`100000u`→`100000000u`, ns→ps) dávají shodný výsledek periody, ověřeno
  ručně (100 µs okno / 1000 period = 100 ns perioda, shoda v obou jednotkách).
- **`app_gpsdo.c:8489`** — `fpga_freq_dt_ticks(fm.gate_time_ns) *
  FPGA_TICK_PS` rekonstruuje přesné `dt_ps` z ticků (ticky jsou exaktní,
  `FPGA_TICK_PS=2500` přesně) — korektní vstup pro `mp_period_sample_s`,
  který teď očekává pikosekundy.
- **Emulátor** (`sim_build_frame`) — staví rámec **stejným postupem jako
  FPGA** (`spi_app.v`): celé periody, tiky od náhodné fáze, `gate_ns` jako
  floor — takže testy teď skutečně cvičí vadu, kterou dřívější emulátor
  (libovolný celočíselný gate) nemohl ukázat.
- **HW ověření** (z předchozí relace, 2026-09-27): opakovaně přesná hi-res
  hodnota na asynchronním kmitočtu, žádný systematický posun z floor
  hradla — potvrzeno na desce.
